# 项目wei
## 1. 项目概述

### 1.1 项目名称

个人导航页（Personal Navigation）

### 1.2 项目定位

这是一个部署在 Cloudflare Pages 上的极简静态网站，用于集中管理和访问个人部署的服务、开发项目以及其他常用入口。

它本身不提供复杂业务功能，核心作用只有一个：

> 作为个人服务和项目的统一入口。

用户打开个人域名后，可以通过页面上的导航卡片快速进入其他项目。

### 1.3 项目目标

通过这个项目实现以下目标：

1. 制作一个实际可使用的个人导航页面。
    
2. 学习基础 Web 页面开发。
    
3. 熟悉 Git/GitHub 的项目管理流程。
    
4. 学习 Cloudflare Pages 的静态网站部署。
    
5. 将个人域名与实际项目结合起来。
    
6. 体验一次从本地开发到线上部署的完整流程。
    

这个项目同时作为一个小型 Web 开发实践项目，而不是单纯追求网站功能。

---

# 2. 第一版目标

第一版采用 MVP（Minimum Viable Product，最小可行产品）思路。

只实现必要功能，不提前设计复杂系统。

### 第一版必须实现

- 一个首页
    
- 简洁的页面布局
    
- 导航卡片
    
- 项目/服务分类
    
- 外部链接
    
- PC 端正常显示
    
- 手机端正常显示
    
- GitHub 管理源码
    
- Cloudflare Pages 部署
    
- 自定义域名
    

### 第一版暂时不实现

- 用户登录
    
- 数据库
    
- 后端
    
- 管理后台
    
- CMS
    
- Vue / React 等前端框架
    
- 在线编辑导航
    
- API
    
- 用户系统
    
- 复杂动画
    
- 服务状态监控
    
- 自动获取项目列表
    

原则：

> 能用 HTML + CSS 解决的问题，就不要为了“技术含量”增加复杂技术。

# 4. 导航卡片

导航卡片是整个网站最核心的 UI 元素。

每张卡片建议包含：

- 名称
    
- 简短描述
    
- 可选图标
    
- 点击后跳转的地址
    

例如：

```text
┌────────────────────┐
│ Rclone Tray        │
│ Windows rclone     │
│ 管理工具            │
│                    │
│ → 查看项目          │
└────────────────────┘
```

卡片不需要承载大量信息。

目标是：

> 让用户能够快速判断“这是哪个服务”，然后点击进入。

---

# 5. 导航分类

第一版可以使用以下分类：

### 项目

用于展示自己开发的软件或项目。

例如：

- Rclone Tray
    
- 未来开发的其他项目
    

### 服务

用于进入自己部署的服务。

例如：

- Wiki.js
    
- Jellyfin
    
- OpenList
    
- 其他自部署服务
    

### 其他

用于放置不属于上述分类的入口。

例如：

- GitHub
    
- 个人知识库
    
- 其他常用网站
    

如果实际项目数量较少，也可以暂时取消分类，直接统一显示导航卡片。

# 6. 技术方案

## 6.1 前端

第一版采用原生 Web 技术：

```text
HTML
CSS
```

JavaScript 暂时不是必须的。

只有当后续确实出现需要动态处理的功能时，再加入 JavaScript。

不使用：

```text
React
Vue
Next.js
Nuxt
```

等框架。

原因：

这个网站本质上是一个静态页面，引入前端框架会增加项目复杂度，但不会明显增加实际价值。

# 8. Git 管理

项目从开始制作时就建立 Git 仓库。

建议使用 GitHub 保存远程仓库。

基本流程：

```text
本地开发
    ↓
git add
    ↓
git commit
    ↓
git push
    ↓
GitHub
```

建议按照功能进行提交，而不是做完所有内容后只提交一次。

例如：

```text
Initial project
Add basic HTML structure
Add navigation cards
Add responsive layout
Add project links
Improve mobile layout
Update navigation
```

这样可以顺便练习正常的软件开发版本管理。

---

# 9. Cloudflare Pages 部署

部署目标：

```text
GitHub Repository
        ↓
Cloudflare Pages
        ↓
自动部署
        ↓
个人域名
        ↓
导航页面
```

网站源码存放在 GitHub。

Cloudflare Pages 负责部署静态网站。

以后修改代码并推送到 GitHub 后，可以由 Cloudflare Pages 自动重新部署。

这样可以形成一个简单的 CI/CD 流程。

# 10. 域名规划

个人导航页可以作为个人域名的主入口。

例如：

```text
example.com
```

对应：

```text
个人导航页
```

其他服务可以使用不同的子域名：

```text
wiki.example.com
media.example.com
files.example.com
```

最终形成：

```text
                    example.com
                         │
                   个人导航页面
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
       项目入口        服务入口        其他入口
          │              │
          ↓              ↓
     Rclone Tray      Wiki.js
                     Jellyfin
                     OpenList
```

需要注意：

导航页只是“入口”，不负责承载其他服务。

其他服务依然独立部署。

# 11. 响应式设计

网站至少需要适配两种使用场景：

### PC

可以使用多列卡片布局。

例如：

```text
┌────────┐ ┌────────┐ ┌────────┐
│ 项目 A │ │ 项目 B │ │ 项目 C │
└────────┘ └────────┘ └────────┘
```

### 手机

自动变成单列或较少列：

```text
┌──────────────┐
│    项目 A    │
└──────────────┘

┌──────────────┐
│    项目 B    │
└──────────────┘
```

第一版不需要追求复杂的响应式效果。

只要：

- 文字不溢出
    
- 卡片不变形
    
- 链接容易点击
    
- 页面可以正常滚动
    

即可。

# 12. UI 设计原则

整体风格建议：

> 简洁、清晰、低干扰。

不要为了展示技术而添加大量：

- 动画
    
- 粒子效果
    
- 3D
    
- 背景视频
    
- 复杂交互
    
- 滚动特效
    

导航网站最重要的是效率。

用户应该能够：

```text
打开页面
↓
找到目标
↓
点击
↓
进入服务
```

最好几秒内完成。

# 13. 第一版开发流程

建议按照下面的顺序完成。

## 阶段 1：确定导航内容

先整理自己准备放进去的服务和项目。

例如：

```text
项目：
- Rclone Tray

服务：
- Wiki.js
- Jellyfin
- OpenList

其他：
- GitHub
- 个人知识库
```

暂时不考虑页面代码。

---

## 阶段 2：设计页面结构

确定：

- 页面标题
    
- 分类
    
- 卡片内容
    
- 页面布局
    
- 移动端布局
    

可以先画一个简单草图。

---

## 阶段 3：创建项目

创建 GitHub Repository。

建立：

```text
index.html
style.css
assets/
README.md
```

完成最基本的 HTML 页面。

---

## 阶段 4：制作 UI

按照设计实现：

1. 页面整体布局
    
2. 标题
    
3. 分类
    
4. 导航卡片
    
5. 链接
    
6. 响应式布局
    

---

## 阶段 5：本地测试

至少检查：

- PC 浏览器
    
- 手机浏览器
    
- 不同窗口宽度
    
- 所有链接
    
- 页面文字
    
- 图片/图标
    
- 点击区域
    

---

## 阶段 6：部署 Cloudflare Pages

将 GitHub Repository 连接到 Cloudflare Pages。

完成：

```text
GitHub
↓
Cloudflare Pages
↓
网站上线
```

---

## 阶段 7：绑定域名

将个人域名指向 Cloudflare Pages。

最终达到：

```text
你的域名
↓
个人导航页
↓
其他服务
```

# 16. 项目范围控制原则

这是本项目非常重要的一部分。

第一版的目标不是：

> 做一个完整的个人网站。

而是：

> 做一个真正能用的个人导航页。

如果开发过程中出现以下想法：

```text
是不是应该加数据库？
是不是应该做后台？
是不是应该做登录？
是不是应该用 Vue？
是不是应该做 CMS？
是不是应该做 API？
```

先记录到 TODO，不立即实现。

可以遵循：

> 先完成 MVP，再根据实际使用产生的需求进行迭代。

# 17. 项目的学习价值

这个项目虽然很简单，但可以覆盖一条完整的基础 Web 项目流程：

```text
需求分析
    ↓
页面设计
    ↓
HTML / CSS
    ↓
Git
    ↓
GitHub
    ↓
Cloudflare Pages
    ↓
DNS / 域名
    ↓
自动部署
    ↓
线上维护
```

与 Rclone Tray 项目相比：

```text
Rclone Tray
→ Python
→ 桌面软件
→ 软件工程
→ Windows
→ 打包发布

个人导航页
→ HTML / CSS
→ Web
→ Git
→ GitHub
→ Cloudflare
→ DNS
→ CI/CD
```

因此它可以作为一个低难度但完整的 Web 实践项目。
