# 2026-11-01 迁移到 Workers：修复远程构建失败

## 现象

提交 `2ae4e3e`（首页迁移为沙漏视觉页）推送后，GitHub 上的 check run
`Workers Builds: personal-navigation` 结论为 `failure`；`started_at` 与
`completed_at` 同为 `06:19:27Z`，即**在构建开始前就失败**（0 秒），
不是打包或上传阶段出错。此前 `c390bb3` / `405372b` / `bc1570c` / `d3d9e03`
四个提交均为 `success`，线上仍是旧版本。

## 定位

线上部署目标是 **Worker** 服务 `personal-navigation`（Workers Builds），
而仓库按 Cloudflare Pages 的约定组织（根目录静态文件 + `functions/api/status.js`），
一直依赖 Workers 的「自动配置」（auto-config）来部署。

用本地 wrangler 4.156.0 在仓库副本上执行 `wrangler deploy --dry-run`，复现同类错误：

```text
X [ERROR] This project has a `functions` directory and static files in its root,
which looks like a Cloudflare Pages project using Pages Functions.
Automatic configuration cannot migrate Pages Functions to Workers yet, and deploying
the project root as static assets would leave the Functions undeployed.
```

结论：新版本 wrangler 在自动配置阶段拒绝「根目录静态文件 + `functions/`」的组合，
于是 Workers Builds 的 auto-config 在 0 秒内失败。与本次提交内容无关，
是工具链升级把此前能跑的隐式配置判成了非法。

## 修法

选择官方建议的迁移路径：显式配置 Worker，把 Pages Function 换成 Worker 路由。

| 变更 | 说明 |
| --- | --- |
| `index.html` / `nav.html` / `status.html` / `_headers` / `css/` / `js/` / `assets/` → `public/` | 静态资源根目录，`assets.directory` 指向它，URL 路径不变 |
| 删除 `functions/` | Pages Functions 约定目录，Worker 不识别 |
| 新增 `src/index.js` | Worker 入口：`/` → `/index.html`，`/api/status` → `status.js`，其余 `/api/*` → 404 |
| 新增 `src/status.js` | 由 `functions/api/status.js` 逐行移植，`onRequest(context)` → `handleStatus(env)` |
| 新增 `wrangler.jsonc` | `main` / `assets` / `compatibility_date`，构建不再走 auto-config |

`wrangler.jsonc` 关键项：

```jsonc
"assets": {
  "directory": "./public",
  "binding": "ASSETS",
  "html_handling": "none",
  "run_worker_first": ["/", "/api/*"]
}
```

两个非默认值的原因：

- `html_handling: "none"`：默认模式会把 `/status.html` 重定向到 `/status`。
  `_headers` 里 `/status.html` 的 `connect-src 'self'` 规则按字面路径匹配，
  重写后状态页会落到 `/*` 的 `connect-src 'none'`，`fetch('/api/status')` 被 CSP 拦掉。
- `run_worker_first` 显式包含 `/`：`html_handling: "none"` 下没有文件能匹配根路径，
  `/` 会 404；由 Worker 转发到 `/index.html`。
- `compatibility_date` 取 `2026-10-01`：本机 workerd 支持的最新日期为 `2026-10-30`，
  写成当天日期（`2026-11-01`）本地运行时直接拒绝启动。

## 验证

`npx wrangler deploy --dry-run`：读取 `public/` 27 个文件，Worker 包 4.23 KiB，
无错误。

`npx wrangler dev` 逐路径实测：

| 路径 | 结果 |
| --- | --- |
| `/` | 200，`text/html`，`<title>个人导航 — Benincasamatch</title>`，CSP 生效 |
| `/index.html`、`/nav.html`、`/status.html` | 200，无重定向 |
| `/css/sandglass.css`、`/js/sandglass.js`、`/assets/fonts/Geist.woff2`、`/assets/headimg/blue.png` | 200，`content-type` 正确 |
| `/status.html` | 响应头 `connect-src 'self'`（`_headers` 路径规则生效） |
| `/api/status`（无密钥） | 500 `{"ok":false,"error":"服务未配置…"}` |
| `/api/status`（`--var UptimePageApiSecret=dummy-key`） | 502 `{"ok":false,"error":"UptimeRobot API 调用失败：api_key is invalid."}`，证明变量名与上游调用链路正确 |
| `/api/nope` | 404 |
| `/readme.md`、`/wrangler.jsonc`、`/src/index.js`、`/_headers` | 404，未作为静态资源发布 |

另：`_headers` 被 wrangler 解析为 3 条规则（`/*`、`/status.html`、`/assets/*`）。

## 后续注意

- 新增页面必须放进 `public/`，放在仓库根不会被发布。
- 若删除 `public/_headers` 中 `/status.html` 的 CSP 覆盖块，状态页会因
  `connect-src 'none'` 拿不到监控数据。
- Worker 的环境变量名保持 `UptimePageApiSecret`，改名需同时改 `src/status.js`。
- 自定义域名与 Workers 路由的绑定不在仓库内，迁移只换了 Worker 内部结构，
  `personal-navigation` 服务名未变，域名绑定无需改动。
